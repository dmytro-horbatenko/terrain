## Изменения Terrain

| Часть | Что реализовано |
|---|---|
| Первая попытка | Импорт блокирует несколько оценок одного `promptId` в одном payload. Preview сохраняет строки и заметки, показывает неоднозначность, не предлагает ложное изменение расписания. Исправления предлагается сохранить в заметке исходной попытки. |
| Отложенная проверка | После успешного импорта фактической практики появляется переход к существующей форме Skill check нужной темы. Открытие формы ничего не планирует и не засчитывает. |
| Практика и продолжение | В теме доступны ссылка на артефакт, файл/версия, выполненная команда, наблюдаемый результат, использованная помощь и следующий шаг. Они сохраняются в прежнем application event. Последняя сохранённая ссылка доступна для продолжения. |
| Черновики | Несохранённая запись практики участвует в предупреждении при выходе и смене темы. Ошибка сохранения сохраняет ввод; успешное сохранение очищает форму. |
| Диагностика | Conduct ограничивает проверку сомнительных предпосылок одной–тремя открытыми попытками в сумме и требует дождаться ответа. Ошибка не превращается в уверенный диагноз или автоматическое сокращение курса. |
| Обратная связь | Уточнены наблюдаемая ошибка, ожидаемый результат, постепенное уменьшение подсказок и изменённое условие для переноса. Неоднозначная задача/рубрика не должна давать ложную оценку. |
| Источники | Четыре source plans в каталоге уточняют границы Shanghai Yellow Paper и необходимость fork-matched execution specs. Личные конспекты и текущее состояние ученика не переписаны. |

## Использование и оставшиеся шаги

1. Локальные изменения приложения готовы к просмотру. Для доступности в рабочем
   Terrain нужны обычная публикация/deploy и последующая UI-проверка. Миграций БД
   в этой работе нет. Изменения source plans для уже импортированных тем должны
   пройти штатное обновление каталога с сохранением пользовательских изменений.
2. Для публикации локальных коммитов: подключить приватный remote и отправить
   ветку. При настройке второго
   Mac сначала сопоставить его возможную несохранённую работу, затем клонировать
   или обновить копию; не заменять существующие файлы вслепую.
3. На обоих Mac использовать один аккаунт и один сервер Terrain для заметок и
   прогресса. Git переносит учебный код; clone приложения не синхронизирует БД.
4. Проверить реальный цикл A → B → A с одним commit, одинаковыми проверками и
   сохранённым следующим шагом. До этого не считать перенос проверенным.
5. Затем выполнить [небольшой личный пилот](../learning/personal-learning-pilot.md):
   реальные отложенные попытки, помощь и ошибки, удобство продолжения. Результатов
   пилота пока нет; улучшение обучения не объявляется доказанным.

Рабочий ритм: одна глубокая тема и один этап проекта; практика → фактический
результат и помощь → сохранённый код/следующий шаг → изменённая задача позже.
Wallet, indexer и escrow дополняют полный курс по мере готовности.
